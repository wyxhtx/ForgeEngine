## 二、项目事实

- **技术栈**：C++20 + Vulkan（`VK_EXT_MESH_SHADER` / `VK_KHR_swapchain`）。
- **依赖**：vcpkg manifest（13 依赖直列 + `config\vcpkg\` overlay 9 端口）；GLFW / tinygltf / KTX2 / FastNoise2 / OpenAL + MSDF 文本栈（freetype / msdfgen / msdf-atlas-gen）。
- **定位**：无限体素世界 3D 沙盒引擎。
- **命名**：ForgeEngine = 引擎（工程/exe/`fe-` 指令）；Forge = 游戏（`src\code\forge`）。
- **主程序**：`src\code\vk\Main.cpp` 单 TU；`Main.h` 含 VMA / tinygltf 的 `*_IMPLEMENTATION`；PCH = `External.h`。
- **配置档**：Debug / Release / RelWithDebInfo（后者 = 快速日常档，`/Od` `/Zi` 带 PDB）。
- **知识库**：`docs\chatbox-docs\` 共 8 份（01~08）。
- **调试指令**：`fe-br`（构建+运行）/ `fe-config` / `fe-st` / `fe-clean` / `fe-done` 等，见 `01_总览.md` 与 `08_工作流.md`。

## 三、核心概念

- 结构：Plate → Chunk（32³ + 34 边缘）→ Cube。
- 参数：`sightRange=8`、`groundPlane=4096`、`originShiftThreshold=256`、`noiseExtreme=2^23`。
- 存储：双存储 full / delta；region 3x3x3。
- 地形网格：贪心网格 + 面剔除 → `terrainVertex` → `Layer_0`（视距 4）/ `Layer_1`（视距 8）。
- 线程：`lockInfo` 多锁 + 原子锁；`kmeans` 分区并行生成。
- 渲染：地形当前走 vert+frag（terrainDeferred）；MeshShader 路子已留位未启用（见 03_源码模块.md）。
- 文本：MSDF（字集＝ASCII ＋ 常用汉字 3500（资产 `src\assets\font\uiText\charset.txt`，缺文件回退 ASCII）＋ `glyphMap` 字形表，**定长补位防命令烘焙截断**；图集有落盘缓存 `storage/local/cache/msdf/`，冷烘焙 12 s → 命中 15 ms）。
- 描述符布局：**启动时反射 spv 现算**（见 `02_构建体系.md`），不手写、不构建期生成。

## 四、代码约定速查

> 完整细则与逐条证据：库 `代码规范` / `代码规范提炼证据`。本节只收纳高频、易错项；冲突时以库为准。

### 4.1 命名

- 数据类后缀：`xxxEnum`=枚举、`xxxInfo`=信息（常量/配置/元数据）、`xxxStruct`=结构体、`xxxList`=结构体列表；管理器/结点带 `Node`，流程对象带 `proc`。
- 单例初始化 `InitXxx`；**唯一类变量初次声明用 `Init + 类名`（`Device InitDevice;`），之后的引用声明直接用类名（`Device& Device;`）**——两者必须可区分。
- 枚举：`namespace xxxEnum { namespace yyyId { enum type { …, count }; } }`；**禁用 `enum class`**；末项哨兵 `count`。
- **枚举类型的变量 / 形参 / 成员一律 `xxxType`**：`pipelineEnum::shaderFlowId::type` ⇒ 变量名 `shaderFlowType`（`primitiveId` ⇒ `primitiveType`、`dynamicId` ⇒ `dynamicType`）；同名形参给同名成员赋值时加 `t` 前缀（`tPipeType` / `tShaderFlowType`）。细则见库 `代码规范`。
- 成员变量不加 `m_`/下划线；尽量不用 `this->`。
- 常量集中 `*Info` 命名空间；**不用 `constexpr` / `static const`**。
- 命名空间排序（世界数据层）：`face` → `cube` → `chunk` → `plate` → `terrain` → `noise` → `storage`。
- 函数名语义对齐既有词：板块更新 = 板块内部区块数组更新；区块更新 = 区块内部方块数组更新。
- **改名一律先与用户探讨**。

### 4.2 传参

- 总则：**枚举按值、标量按值；结构体/数据结构/类按 `const Xxx&`**。
- Vulkan 句柄沿用 `const Xxx&`。
- 字符串/路径：类型 `std::string`，形参 `const std::string&`；只在 C API 调用点 `.c_str()`。
- `t` 前缀**只用于"结构体/类下用同名形参给同名成员赋值"**（`: isEnable(tEnable)`）；已存在的 `t` 不清理。
- 纹理参数放最后；默认值写在签名里；**参数表不跨行**。

### 4.3 声明与生命周期

- RAII：构造/析构对称；生命周期用 `isEnable` + `clear` 管理。
- 成员置顶；访问级别不变；**成员区内部原有分组空行原样保留**。
- **只有真构造函数算"构造"**（`Xxx()`、`Xxx() = delete`、`~Xxx()`）；`create<结构体名>()` **不算构造函数**，归创建组。
- **同名遮蔽**：成员名与所用类型同名时（如 `Device& Device;`）——成员名不动、**成员块原位不动**（上移会导致类型名被遮蔽 → `error C2327` 连锁失败）；签名里直接用类名，不加 `::` 限定。

### 4.4 结构体 / 类排版

- 两对：第一对 = 构造（公开 = 构造函数族；私有 = 构造期内部实现）；第二对 = 对外（公开 = 对外接口；私有 = 其内部实现）。class 与 struct 同规则；**class 的纯函数声明也按函数项参与分组**。
- 四组顺序固定：① 构造函数族 → ② 创建·重建·清理（只认本结构体自己的生命周期入口；`create` → `recreate` → `clear`；**跨访问段也要并到一起**）→ ③ 同段内其余对外（不再按前缀分族）→ ④ 同段内其余私有（`createBuffer`/`createPool` 等创建辅助保持 private）。 **规则B（2026-10-01）**：`create*`/`recreate*`/`clear*` 若在**私有段**（= 无外部引用，纯内部辅助），一律不算创建族、留在本段「其余私有」；只有公开/保护段才按「全部调用者都是构造/生命周期入口」判入创建族。
- **成对函数**（`getXxx`/`setXxx`、`beginXxx`/`endXxx`、`createXxx`/`clearXxx`，含无后缀的 `begin`/`end`、`create`/`clear`）必须**前后一对、紧挨着**，且 **get / begin / create 在前**（例：`begin → end → beginRender → endRender`）；`record`/`wait` 这类同基名非一对不算；`recreate` 夹在 create/clear 之间不算破对；日后 `enable`/`disable` 等同理。
- **同后缀家族**（同段内、末位驼峰词相同、彼此不互相调用的兄弟函数，如 `mouseHandle`/`keyHandle`/`scrollHandle`）视为一个子块、**强制相邻同层**：不可达成员并入族内已知层、块内空 1 行；族内被调用的辅助函数（如 `updateView`）留在族块之后、跨层空 3 行。**排除**：族内成员分属不同已知调用层、派生名（`isHandleChangeCubeList` 之于 `handleChangeCubeList`，忽略大小写）、族内互相调用、构造/创建族与 get/set 成对族。
- **嵌套 struct/class 与其后紧跟的运算符重载（`operator==` 等）算同一组**。
- **空行只用 1 行或 3 行、禁 2 连空**：组内空 1 行；创建组 ↔ 其余对外组之间固定 3 行；组与 `public:`/`private:` 标签之间空 1 行、标签与首项紧邻；**容器的最后一项与闭合 `};` 之间 0 空行**。
- **`else` 独立成行**（禁 `} else {`）。
- **`isEnable` 守卫一律包裹式** `if (isEnable) { … }`（禁 `if (!isEnable) { return; }` 提前返回，其余启用开关同理）。
- 函数内按调用层分组（class 全段；**struct 只私有段**）：构造函数直接调用的 = 第 0 组，只被第 0 组调用的 = 第 1 组，依此递推；同一函数被深浅两层调用时**取更浅的那组**；**组规则只适用 L1（构造函数直接调用那一层）**，更深层按调用先后、无组边界；组内空 1 行、组间空 3 行。 **规则C（2026-10-01）**：struct 的**私有段**也按调用层分组 —— 入口 = 构造族 ＋ 公开/保护段的函数项；跨层空 3 行；成对（get/set、create/clear）与同后缀家族先行捆绑、不被分层拆散；struct 其余段仍按「成对优先」。
- 排版脚本：`cmd\reformat-structs2.ps1`（默认干跑；`-Path <文件>` 指定；`-Apply` 落盘）。

### 4.5 书写格式

- 一条语句一行（禁多条挤一行）；**签名 + 初始化列表 + `{` 写在同一行**。
- 缩进：`src\code` 全树 **Tab**。
- 注释/报错用中文；字段与参数给短中文注释。
- 性能注释格式：`//创建板块，RM_0.4.6（8_32：1300）`。
- 待办统一 `//todo`（小写无空格）；**不用 `FIXME`**。
- 类型转换**一律 `static_cast`、禁 C 风格 `(T)`**；函数指针 / `void**` 用 `reinterpret_cast`。
- 同一文件内函数按调用顺序排列（顶层在上、底层在下）。
- **一行数据派生的同一写法只写在结点里**：管线结点（`pipelineStruct::pipelineNode`）凡"由本行字段派生的同一表达式"（如 `isMsaa ? msaa : VK_SAMPLE_COUNT_1_BIT`）收进结点方法（`getMsaa(msaa)`），调用点直接调方法，**不在各处复制同一个三元 / 判断**。
- **中文注释列对齐依赖"汉字宽度 = 半角 × 2"的字体**：注释列由工具按"汉字 = 2 显示列"补 Tab（`cmd\align-comments-v17.ps1`），所以**编辑器/终端字体必须严格 2:1**；本项目已定 **`Maple Mono Normal NF CN`**（实测 拉丁 0.6em / 汉字 1.2em = **2.000**，拉丁是正常宽度、不是被压扁的窄体）。备选：`Cascadia Next SC`、`Noto Sans Mono CJK SC / 思源等宽`（均实测 0.5em / 1.0em = 2.000）。判据只看**比值是否为整数**（em 绝对值无所谓）。**`Consolas` / `Cascadia` 无汉字字形，回退微软雅黑后为 1.819 ⇒ 中英混排注释列必逐行漂**，看到列不齐先查字体。**能否用 Tab 顶列取决于编辑器：VS 的"列" = 显示列 ⇒ 可以用 Tab**（见下条）；文本终端等按字符列推进的编辑器不行。

- **行尾注释列对齐（Tab 版，2026-09-25 定；v17 加固）**：① VS 的"列"是**显示列**（实测：4 汉字 + Tab 与 8 半角 + Tab 同列 = 13 ✓），所以 **Tab 可以对齐**，不需要用空格；② **显示宽度表必须来自字体实测** —— `cmd\align-comments-v17.ps1 -FontPath <ttf>` 用 `GlyphTypeface` 读每个字符 advance 归档（半角基准 = `M`；实测 `·` `≤` `≥` `×` `→` = **1 列**，CJK 与全角标点 = **2 列**，**别按码点猜** ✗）；③ 三列 = `代码 → //`、`//中文 → 功能前半（含：）`、`功能前半 → 冒号后说明`，用 **Tab 顶到目标列**（目标列取**全文件统一**值 ⇒ 跨枚举同列）；④ 验收三件套：**自校验**（列组唯一、不一致 0）+ **幂等**（再跑 0 改动）+ **编译** Release/Debug 0 错 0 警；⑤ **v17 加固（2026-09-26）**：**只重排源文件里已经存在的 Tab 边界** —— 作者写空格或直接相接处就是"作者的列边界"，工具**不新造列、不压缩注释文本、末列不补尾 Tab**；参与门槛 = 代码部分为"裸标识符 + 可选逗号"（枚举/表格列条目），语句行与正文注释不参与；**默认作用域 `src\code\vk\data`**，全树必须显式 `-All`（在 `src\code` 副本上实测：`-All` 会去动 `forge\data\ForgeEnum.h` 等 ✗）；改前用 `-Preview N` 看前后对照；**样板 = 用户精修的 `src\code\vk\data\VkEnum.h`，工具对它必须 0 改动**（否则是工具判据错，不是文件错）；与 VS 逐行对拍用 DTE 的 `TextPoint.DisplayColumn`（VS **必须非管理员**启动 ✗）。

### 4.6 文件与编码

- 源码与文档：**UTF-8 无 BOM**、**CRLF**、**末尾无尾换行**（库内文档例外：`01`~`05` 为 LF、`06`~`08` 为 CRLF；改前先看原文件）。
- `*.ps1`：**必须带 BOM** + CRLF。
- 头文件用 `#pragma once`（不用 include guard）；namespace 结束不写 `// namespace xxx`。
- **内部头不得自带 include**（include 只集中在 `External.h` + `Main.h`）；`Main.h` 段内次序是作者有意设计——**遇到依赖顺序问题先与作者确认**，不要自行重排、也不要在头里补 include。（历史示例：曾用位移一行 include 解决——`tool/SpirvReflect.hpp` 需 `VkInfo.h` 的 `spirvInfo`；该头已并入 `VkStruct.h` 的 `descStruct::spirvTool`。）
- **系统库 include 的唯一落点＝`External.h` 的 `/*系统库文件*/` 段**（2026-09-30 定）：所有 `#include <…>` 集中写在这里、**按名称升序**，各文件不再写系统 include（不靠 GLFW/glm/VMA 捎带）；带 `*_IMPLEMENTATION` 的三方头（VMA/tinygltf）留在 `Main.h` 唯一 TU、不进 PCH。
- 改动必须**保留原 EOL**；改后自检 BOM / EOL / 尾字节并报告。
- 文件末尾直接 EOF（末行就是 `}` / `};`）。

### 4.7 工具与验证

- 批量排版改动必须过三关：**非空行多重集一致（大小写敏感）+ 幂等（再跑 0 变更）+ 编译 0 错误 0 警告**。
- 落盘前备份，失败整体回滚；备份与临时件统一 `build\temp\`（`bak`/`log`/`probe`/`work`）。
- 自研构建期工具若输出中文，**要按消费者代码页转码**（历史教训见 `06_经验教训.md`）。
- 受限沙箱下构建一律带 `-p:TrackFileAccess=false`（命名管道被禁）；它会跳过"生成物 → 重编"跟踪，验证生成物改动时需强制重编。

### 4.8 错误处理与日志

- Vulkan 调用一律检查：`if (vkXxx(...) != VK_SUCCESS) { Log::printError(__FILE__, __LINE__, "…失败"); }`。
- 日志走 `Log` 命名空间；**`printError` 内部 `while(true);` 挂起**（只报错、不修复），**调用点之后的 `return` 是有意保留、不作死代码清理**。
- 项目内**不用异常、不用 `assert`、不调用 `exit`**。
- **哪种 `printError` 该包 `debugInfo::LogSwitch`**：条件**只可能因我们自己代码/配置写错**而成立（`maxSet == 0`、写入的 binding/类型与布局表不一致、管线着色器数量不对…）→ 写成 `if (debugInfo::LogSwitch && 条件) { Log::printError(…); }`，发布档关日志即零成本、也不会挂起卡死玩家；条件**可能因驱动/显存/硬件/资产文件/环境**而成立（`vkXxx != VK_SUCCESS`、模型/纹理内容异常…）→ **一律无条件**保留，若不想挂起就改 `printWarning`，**别让日志开关把它吞掉**。
- **"表驱动"的角色要有唯一入口，别留隐式键**：管线创建已改 9 处显式 `createPipelineNode<管线 id>(…)`（2026-09-28 删掉 `procPipelineShader` 总表与 `checkPipeKey` 自检）—— 管线 id 走**模板实参**、顶点类型走 `pipeVertexType<Id>` 编译期映射，写错直接编译不过；按枚举排的预设表（`xxxList`）仍靠构造函数 `for (i < count)` 逐项译入，加枚举项时务必在 `createXxx` 的 switch 里补 `case`（`count` 也在枚举里，C4062 默认不开，漏了不会报错）。

## 八、命令行 / 脚本执行教训

- 执行前检查：无占位符、无历史提示符混入、PS7 用 `Join-Path $PWD`、here-string 先存变量、替换先长后短、preset 严格 JSON。
- 写/改文件的脚本：**路径变量别用 `$p`/`$f` 这类短名**（`foreach ($p in $ps)` 会覆盖它，落盘会写到名为 `System.Collections.Hashtable` 的垃圾文件，脚本还照样报"已写"）；路径用 `$path`，循环变量加后缀（`$pr`/`$it`）。
- 脚本自报"已写" ≠ 文件真变了：落盘后必须比对**写入前后 hash** + 回读关键区段自证。
- 管道接 `Select-Object -First N` 会**提前终止上游**：凡要写文件的脚本先存变量再筛选（构建命令同理，会半路掐断构建并残留进程）。
- 受限沙箱下 .NET 静态调用可能解析异常（如 `[System.IO.File]::GetLastWriteTime`），改用 cmdlet（`(Get-Item $path).LastWriteTime`）。
- 批量重排/格式化类改动必须"合成扰动"自证：复制一份打乱 → 跑脚本看能否修回 → 与真实文件逐行比对（0 差异才算过）；另做幂等 + 多重集不变校验。
- 用编辑器/工具改 `.ps1` 后必须复检编码——这类写盘会**丢 BOM 并把 EOL 变成纯 LF**，改完用 `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($true)))` 写回并自检 BOM/CRLF 计数。

## 2026-10-01 写法约定补充（按当前代码）

- **两阶段拆分**：CPU 段（可并行、零 Vulkan）与 GPU 段（主线程）分开命名（`loadKtx` / `uploadKtx`），中间产物用小结构体承载（`ktxLoadNode`：结果 + 是否需要写缓存 + 缓存路径 + 错误）
- **线程边界**：工作线程**不得**调 `Log::printError`（打印后 `while(true);` 挂起）⇒ 错误码经结构体回主线程再报；**Vulkan 调用一律主线程**
- **顺序铁律**：`DeflateZstd` 会压掉内存块数据 ⇒ **先上传 → 后压缩 → 再写盘**
- **临时打点**：`Log::stopwatchNode`（`src\code\vk\tool\Log.hpp`），注释固定写 `//临时计时（量完删）`，量完**删净并自查残留 0**
- **锚点写入**：形状校验（目标行内容）＋越界校验（插入点 < 下一函数头）＋花括号平衡 == 0，任一不满足 ⇒ **不写盘**
