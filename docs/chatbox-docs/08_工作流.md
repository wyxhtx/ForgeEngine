## 协作协议要点

- **影响卡先行**：改动前给"方案影响卡"（文件 / 逻辑 / 风险 / 回滚）→ 等用户确认。
- **命令块三段式（改 → 验 → 提交）**：多文件/命令改动 = ①改 ②验证带预期 ③提交；单文件改动 = 给完整文件。
- **命令块开头一律 `cls`**：清屏，防历史输出/提示符混入误判；破坏性命令附回滚。
- **验证贴回核对**：用户执行后贴输出，dsh 判读推进；输出精简，只贴验证结果/报错行。
- **提交纪律**：每逻辑单元一次 commit；勿逐小步急交；git 永远用户手动。
- **T 模板**：T1 方案讨论 / T2 解释 / T3 单文件 / T4 多文件命令块 / T5 诊断 / T6 审查（分级清单）。
- **任务卡**：【类型】【对象】【约束】。
- **沉淀**：修复类收尾把可复用教训追加到 `06_经验教训.md`（查重后），与 commit 同批。

## 模型贴图 BC7 缓存（2026-10-01 落地）

**链路**：源贴图 `src/assets/image/model/**/*.ktx2`（Basis 超压缩；`vkFormat=UNDEFINED` + `KTX_SS_ZSTD`）
　─首次启动─▶ `loadKtx()` 解码 + `TranscodeBasis(BC7)` ─▶ `uploadKtx()` 上传 ─▶ `ktxTexture2_DeflateZstd(3)` ─▶ 写缓存
　─之后启动─▶ 直接读缓存（`ktxTexture2_NeedsTranscoding` 自校验）⇒ 零转码

**落点**：`storage/local/cache/ktx/<源路径扁平化>.bc7.ktx2`（`fileInfo::path::ktxCachePath`；**随进程工作目录**，与 `pipeline.bin` 同机制；删了会重建）
**开关**：`engineInfo::ktxCacheSwitch` —— 关：不读不写、每次运行期转码；开：首跑写缓存、之后命中
**体积**：4 张模型贴图 69.34 MB（BC7）→ **25.19 MB**（BC7+ZSTD，无损，`KTX_SS_ZSTD`）
**收益（实测）**：模型加载段 未命中 793 → **557 ms**（并行后）；命中 **128 ms**（转码归零）
**顺序铁律**：**先上传、后 `DeflateZstd`、最后写盘** —— `DeflateZstd` 会把内存里的块数据压掉，先压就没法上传
**并行**：A 段 `loadKtx()` 纯 CPU ⇒ 多线程（上限 `std::thread::hardware_concurrency()`，工作窃取）；B 段 `uploadKtx()` 含 Vulkan ⇒ 主线程；工作线程**不得**调 `Log::printError`（挂起语义），错误经 `ktxLoadNode::error` 回主线程
**注意**：缓存文件头可能被 ktx 按 DFD 标成 `BC7_SRGB`，但引擎统一按 `VK_FORMAT_BC7_UNORM_BLOCK` 建 image ⇒ 不影响采样
## 大改自愈流程（2026-10-01 定，配合铁律 8）

1. **备份**：每个将改文件 → `build\temp\bak\<文件>.<意图>前-<日期>`
2. **锚点写入**：形状校验（目标行内容）＋越界校验（插入点 < 下一函数头）＋花括号平衡 == 0；任一不满足 ⇒ **不写盘**
3. **编译**：0 错 0 警；失败 ⇒ **脚本自动回退**（不手工缝补），把失败原因回报用户
4. **三闸门**：编译 0/0 → 探针 `exit=0`（四项 BAD=0）→ 真跑 PASS（VUID 0 / 未销毁句柄 0 / `pipeline.bin` 重写）
5. **量化**：判断优化收益时加**临时打点**（`Log::stopwatchNode`，注释 `//临时计时（量完删）`），量完**删净并自查残留 0**
6. **收尾**：编码自检（仓库 CRLF / 库 LF / 无 BOM / 无尾换行）→ 文档与库同步 → 报告（含「未执行 git 写操作」）
