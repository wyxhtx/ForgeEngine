> 用途：定义 dsh（DeepSeek Harness，本机 AI：方案 + 执行合一）与用户的分工。
> 变更：**2026-09-23 起 Chatbox（原"大脑"）弃用**——此前是"Chatbox 出方案 + dsh 执行"双轨，现由 dsh 单轨承接；双轨时期的记录留在 `06_经验教训.md`。

## 分工

- **dsh（我）**：方案 / 解释 / 审查 / 文档 / 改文件 / 跑命令 / 机械批量活；只改文件，绝不碰 git。
- **用户**：拍板（确认方案影响卡）、构建与运行判读（`fe-br` / VS F5）、`git commit/push`（永远手动）、破坏性动作发话。
- **知识库**：`docs\chatbox-docs\`（01~08）即我的工作手册与事实源，**改动直接生效、无同步步骤**；Obsidian 库 `铸造` 是规范本体（按 AGENTS.md 预授权同步）；`06_经验教训.md` 是踩坑库（改前查重、改后沉淀）。

    完成报告：文件清单 + 行数/位置 + 验证证据 + 编码自检（BOM/EOL/尾换行）

## 协作协议要点

- **影响卡先行**：改动前给"方案影响卡"（文件 / 逻辑 / 风险 / 回滚）→ 等用户确认。
- **命令块三段式（改 → 验 → 提交）**：多文件/命令改动 = ①改 ②验证带预期 ③提交；单文件改动 = 给完整文件。
- **命令块开头一律 `cls`**：清屏，防历史输出/提示符混入误判；破坏性命令附回滚。
- **验证贴回核对**：用户执行后贴输出，dsh 判读推进；输出精简，只贴验证结果/报错行。
- **提交纪律**：每逻辑单元一次 commit；勿逐小步急交；git 永远用户手动。
- **T 模板**：T1 方案讨论 / T2 解释 / T3 单文件 / T4 多文件命令块 / T5 诊断 / T6 审查（分级清单）。
- **任务卡**：【类型】【对象】【约束】。
- **沉淀**：修复类收尾把可复用教训追加到 `06_经验教训.md`（查重后），与 commit 同批。

## 铁律（与 `AGENTS.md` 同步）

1. 绝不执行 git 写操作（commit / push / add 全禁）
2. 只改任务要求的文件；改前给影响卡
3. 编码：md/cpp UTF-8 无 BOM、无尾换行；`.ps1` 带 BOM；保留原 EOL
4. 命名 / 常量 / 变量 / 函数改名先与用户探讨
5. 新增 `src\assets` 目录时提醒确认 VS 工程树可见
6. 破坏性动作（清理 / 删除 / 覆盖）等用户发话
7. 规范 / 约定变更按预授权同步进 Obsidian 库
