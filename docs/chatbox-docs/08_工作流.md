# ForgeEngine 工作流（双轨版）

> 用途：定义 Chatbox（大脑）与 dsh（执行体）双轨协作方式。更新于 2026-09-08。

## 分工总览

Chatbox = 大脑（方案/解释/审查/文档，需语义检索 KB）；dsh = 执行体（改文件/跑命令/迭代密集活）。git 永远由用户手动执行。

## 任务路由

| 任务 | 路由 |
|---|---|
| 方案讨论 T1 / 解释 T2 / 诊断思路 T5 / 审查 T6 | Chatbox |
| 单文件小改（方案已定）| Chatbox 给文件 → 用户贴 |
| 变更类任务：**一次粘贴能完成** → Chatbox 给命令块；**否则** → 出 dsh 任务单 | Chatbox 判定 |
| 多轮改→验→修、机械批量改 | dsh（命名改动先探讨）|
| fe-br 构建验证 | 用户或 dsh，用户判读 |
| git commit/push | 永远用户（VS 或 fe-done）|

## dsh 任务单模板

任务：〈一句话+涉及文件〉
约束：只改任务要求的文件；不执行任何 git 命令；改前给影响卡；
完成后报告：文件清单 + 行数/位置 + 编码自检（BOM/尾换行/EOL）。

## 铁律（dsh AGENTS.md 同步）

1. 绝不执行 git 写操作（commit/push/add 全禁）
2. 只改任务文件；改前给影响卡
3. 编码：md/cpp UTF-8 无 BOM、无尾换行；ps1 带 BOM；保 EOL
4. 命名改动先与用户探讨
5. 新增 src\assets 目录提醒确认 VS 可见
6. 改 docs\chatbox-docs 后运行 fe-sync-kb 复制到 docs\chatbox-sync\

## 知识库同步（Chatbox KB）

- 仓库 = 唯一事实源；Chatbox KB = 只读影子（官方无自动同步，issue #2464 Open）
- 同步 = 手动：cd 仓库根 → fe-sync-kb → 先在 KB 删同名旧文件 → 全选拖入 docs\chatbox-sync\
- 同名拖入 = 新增（实测 2026-09-08），务必先删旧
- 触发时机：chatbox-docs 大改后（低频手动，不做自动机制）


## Chatbox 侧执行协议（源自 07_系统提示词.md）

Chatbox（大脑）不改文件，输出方案/命令块由用户执行。核心：影响卡 → 命令块三段式 → 验证 → 提交。

- **影响卡先行**：改动前给 方案影响卡（文件/逻辑/风险/回滚）→ 等用户确认
- **命令块三段式（改→验→提交）**：多文件/命令改动 = ①改 ②验证带预期 ③提交；单文件改动 = 给完整文件
- **命令块开头一律 cls**：清屏，防历史输出/提示符混入误判
- **验证贴回核对**：用户执行后贴输出，AI 判读推进；破坏性命令附回滚
- **输出精简**：只贴验证结果/报错行，不贴全量
- **提交纪律**：每逻辑单元一次 commit；勿逐小步急交；git 永远用户手动（VS 或 fe-done）
- **T 模板**：T1 方案讨论 / T2 解释 / T3 单文件 / T4 多文件命令块 / T5 诊断 / T6 审查（分级清单）
- **任务卡**：【类型】【对象】【约束】
- **沉淀**：修复类收尾自动沉淀 06（查重后追加，与 commit 同批）
