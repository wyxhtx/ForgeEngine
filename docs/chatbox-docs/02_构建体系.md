# ForgeEngine 构建体系（AI 版）

> 用途：改 CMake/vcpkg/依赖/triplet 前先读。讲"做了什么、为什么"，不是配置原文。

## 配置链总览

    vcpkg.json（依赖清单，13 依赖直列）
      ↓ manifest 模式（toolchain 自动触发）
    vcpkg（下载+锁版本+编译+安装到 build\vcpkg_installed）
      ↓
    CMakePresets.json（vs/ninja 两预设，含 triplet/overlay 指向）
      ↓ cmake --preset vs
    CMakeLists.txt（语言标准/配置类型 → 1 MSVC → 2 Vulkan → 3 find_package 群 → 4 自定义手工目标 → 5 主程序(单 TU+PCH) → 显示分组 → 调试目录 → 着色器）
      ↓ VS 生成器
    build\vs\ForgeEngine.slnx + vcxproj

## CMakeLists 结构（按源码注释）

顶部：C++20 标准；CMAKE_CONFIGURATION_TYPES "Debug;Release;RelWithDebInfo" + RelWithDebInfo flags（/DNDEBUG /Od /Zi，链接 /DEBUG /INCREMENTAL）
1. MSVC 全局：/utf-8 /W3（源码按 UTF-8 编译，防中文注释乱码）
2. Vulkan SDK：find_package(Vulkan) + glslangValidator（缺失即终止）
3. find_package 群：官方 CONFIG（glfw3/glm/VMA/Ktx/OpenAL/ALUT/msdfgen）+ 自产 CONFIG（msdf-atlas-gen）；tinygltf 官方无 config → find_path 封装 ForgeTinygltf
4. 自定义手工目标：kmeans（find_path → ForgeKmeans）、fastnoise2（find_path+find_library → ForgeFastNoise，Debug 链 FastNoiseD.lib + FASTNOISE_STATIC_LIB）
5. 主程序：单 TU（Main.cpp）+ target_precompile_headers(External.h)（PCH）+ /bigobj + UNICODE + 非 Debug 撤 _DEBUG + Release /Zi /DEBUG（PDB）
6. 调试工作目录：F5 工作目录=项目根
7. 着色器：include ForgeShader.cmake → GLSL→spv 规则，先于主程序
8. 运行时资源：POST_BUILD 把 src\assets\{shader,image,model,music,font} 镜像到 exe 同级（bin\output\x64\<Config>\src\assets\...）→ 从输出目录直接跑 exe 也能找到资源，免手动拷贝；CMake ≥3.26 用 copy_directory_if_different 只复制有差异的文件（shader_src\、image_src\ 属源，不复制）

附注：
- 配置集 Debug;Release;RelWithDebInfo：去 MinSizeRel；RelWithDebInfo 重定义为"快速日常档"（编译≈Debug、无 STL 检查、带 PDB 可断点）——勿自定义新配置名（vcpkg 只认内置名）
- PCH=External.h（系统+三方稳定头）；带 *_IMPLEMENTATION 的头不能进 PCH（VMA/tinygltf 在 Main.h 单 TU include）
- 显示分组：GLOB+source_group 挂 cmd/config/docs(含chatbox-docs)/assets/code（纯显示不编译）

## triplet（x64-windows-static-forgeengine.cmake）

vcpkg 编译依赖库（含间接共 29 包）的规格：

| 行 | 作用 |
|---|---|
| ARCHITECTURE x64 | 只编 x64 库 |
| CRT_LINKAGE static | CRT 静态(/MT)，不依赖 msvcp*.dll |
| LIBRARY_LINKAGE static | 库静态 .lib（无 DLL）→ 全静态 |
| C/CXX_FLAGS_DEBUG IDL=1 | Debug 编库 STL 级别=1，配 Main.h 防 LNK2038 |

注意：triplet 内容改动 → 包 ABI 变 → vcpkg 全量重建（一次性，跑完即稳）。

## 依赖三分类（config\vcpkg\port\ 共 9 端口）

| 类 | 数量 | 端口 | 锁定 | 位置 |
|---|---|---|---|---|
| 官方直用 | 8 | glfw3/glm/vulkan-headers/vulkan-memory-allocator/stb/msdfgen/openal-soft/freealut | builtin-baseline | vcpkg 内置 |
| 覆盖官方 | 3 | ktx/tinygltf/freetype（overlay 修正上游 port） | baseline + overlay 修正 | config\vcpkg\port\ |
| 纯自定义 | 6 | aarand/subpar/sanisizer/kmeans/fastnoise2/msdf-atlas-gen（upstream 无此 port） | REF commit | config\vcpkg\port\ |

vcpkg.json 直列 13 依赖；间接依赖自动递归（kmeans→aarand/subpar/sanisizer；msdf-atlas-gen→msdfgen[extensions]+freetype；freetype→brotli/bzip2/libpng/zlib）。

## 描述符布局（运行期反射，2026-09）

描述符布局（哪个 binding、什么类型、哪个阶段）不手写、也不构建期生成，改由**引擎启动时反射 spv 现算**。

| 环节 | 位置 | 说明 |
|---|---|---|
| 输入表 | `src\code\vk\data\VkList.h` 的 `pipelineList::procPipelineShader`（行结构体是 `pipelineStruct::pipelineShaderNode`；结构体归 Struct、表归 List） | 每条管线一行：管线 id（行键）、描述符布局 id、渲染模板、采样数、着色器文件。布局用到的着色器集合由它推导（同一布局被多条管线共用则取并集） |
| 反射器 | `src\code\vk\tool\SpirvReflect.hpp` | 自写最小 SPIR-V 解析器（只解用到的 12 个操作码），已与 SDK `spirv-reflect.exe` 真值全量对拍零差异；只做"文件 → 绑定表"，无副作用 |
| 生成 | `data\VkList.h` 的 `procDescriptorNode::reflectLayout()` | 启动时逐布局反射、合并（同一绑定的多个阶段求并集）、校验（集合号非 0、同绑定跨着色器类型/长度不一致 → `Log::printError` 挂起），直接填 `node[id].config` |
| 池上限 | 同上构造函数里的 5 行 | `maxSet` 属应用侧决策（spv 里没有），仍手写，取 `bufferInfo::*Count` |
| 差异表 | `VkList.h` 的 `pipelineList`：`procPipeRaster`（4 行）/ `procPipeDepth`（3 行）/ `procPipeBlend`（1 行）/ `procPipeDynamic`（2 行），行结构体在 `pipelineStruct` | 逐管线差异（图元·光栅 / 深度 / 颜色混合 / 动态状态）只列"与 `pipeConfigNode` 默认值不同的管线"；行内 `mask` 位为 1 的列才覆盖默认值（`pipelineEnum::pipeRasterMaskId` / `pipeDepthMaskId` / `pipeBlendMaskId`） |
| 审计 | 启动日志 5 行 + 配置审计 10 行 | `scenceForward 描述符布局反射完成：3 项 → b0 mvp → b1 light → b2 texSampler`；`skybox 管线配置：3/0/2/0/1/0/3/0/1/0/0/1/0/0/0`（都是 dev-only，`debugInfo::LogSwitch` 包裹） |

要点：
- **改 GLSL 的 binding → 下次运行即生效**：布局按磁盘上的 spv 现算，天然与着色器一致，不存在"生成物过期"；改完 `fe-br`（重编 spv）再跑即可
- **失败时机**：spv 缺失/损坏、集合号非 0、同一布局在不同着色器里类型或数组长度不一致 → 启动时 `Log::printError` 挂起（没有构建期拦截）
- 构建链只剩 `ForgeShader`（GLSL → spv）→ `ForgeEngine`：没有第二个可执行工程、没有生成头、没有生成物目录
- 历史（2026-09）：曾用"构建期烘焙"（工具 `ForgeReflect.exe` 生成 `DescriptorConfig.gen.h`，运行期再反射一遍比对），因收益不足改回运行期现算，那条路的坑留在 06 经验教训

## 常见问答（结论前置）

- 改 GLSL？→ 改 shader_src，fe-br 增量重编对应 spv
- 改 GLSL 里的 binding？→ 布局由启动时反射现算，**无需改 C++**，重编 spv 后直接跑
- 加一条管线？→ 在源表 `pipelineList::procPipelineShader` 加一行（描述符/模板/采样数/着色器），再按需在 4 张差异表里加行（只写与默认值不同的列，用 `mask` 标出生效位），管线创建、布局反射、配置审计同时生效
- 想让某布局多一个绑定？→ 改该布局任一着色器里的 binding 声明，重编 spv 即生效
- 换官方库版本？→ 改 builtin-baseline → cmake --preset vs
- 升级自定义库？→ 改 portfile REF（新 commit SHA）→ cmake --preset vs
- 加库？→ vcpkg.json 一行 / 新建端口 2 文件
- 删库？→ vcpkg.json 删一行 → reconfigure（manifest 自动卸载已装包）
- 全静态意义？→ exe 单文件分发、不依赖运行库 DLL
- spv 不入库？→ .gitignore shader\，每机现编（编译器匹配）
- vcpkg 输出乱码？→ UTF-8 被 VS 按 GBK 显示，显示层无害
- 依赖为何重建？→ triplet/portfile/baseline 变 → ABI 变 → 一次性重装

## 工具链（2026-09 迁 VS2026 后）

| 项 | 值 | 说明 |
|---|---|---|
| VS | **VS2026 18.10**（`E:\tool\app\vs2026`） | VS2022 17.14 保留作兜底（可回滚） |
| 生成器 | **`Visual Studio 18 2026`** | CMake ≥4.2 才有；命令行用 VS2026 自带的 **4.3.1-msvc1**（`...\vs2026\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin`，已前置到 User PATH） |
| 工具集 | **v145**（MSVC 14.51 / cl 19.51） | 生成的 vcxproj 全部 `<PlatformToolset>v145</PlatformToolset>` |
| vcpkg 选 VS | `VCPKG_VISUAL_STUDIO_PATH` **已删除**（让 `vswhere -latest` 选 VS2026）；`VCPKG_PLATFORM_TOOLSET=v145` | 环境变量改动需广播或重开终端 |
| 迁移代价 | vcpkg 全量重建 29 包（实测 6.5 分钟） | 工具集变 → ABI 变 → 二进制缓存不命中，属一次性 |

铁律：**exe 与 vcpkg 库必须同工具链**。改任一侧（生成器 / 工具集 / 环境变量 / 依赖）都要同时改另一侧，否则 LNK2019 `__std_unique_4`。
