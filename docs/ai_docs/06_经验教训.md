# ForgeEngine 经验教训库

> 用途：踩坑先查；AI 修复任务会自动向本文档追加新条目（自动沉淀机制，见文末）。
> 条目格式：现象 → 根因 → 解决 → 防御。按分类排列。

## 编码类

- **现象**：.ps1 中文乱码 / bat 中文乱码
  **规则**：.ps1 = UTF-8 带 BOM；代码/.md = UTF-8 无 BOM；bat/txt = ANSI(GBK)
- **现象**：VS 输出窗 vcpkg 中文乱码（濮濓絽婀...）
  **根因**：vcpkg 输出 UTF-8，VS 按系统 GBK 解码
  **解决**：无（显示层问题）；命令行看正常
  **防御**：构建正常即可忽略，排查用命令行

## PowerShell / 执行类

- **现象**：PS7 里 [System.IO.File]::ReadAllText 相对路径去 system32 找
  **根因**：PS location 与 .NET CurrentDirectory 不同步
  **防御**：脚本内一律 Join-Path $PWD（绝对路径）
- **现象**：粘贴多行命令报 Get-Process / else 报错
  **根因**：复制内容混入历史提示符；交互式 if/else 分行
  **防御**：只复制代码块本体；if/else 写单行；整块一次粘贴勿逐行敲
- **现象**：占位符 <...> 被原样执行，覆盖文件
  **防御**：执行前确认无 < 占位符未替换
- **现象**：here-string 直接放方法参数 → ParserError
  **防御**：先存变量（$x = @'...'@）再传参
- **现象**：字符串 Replace 不命中（静默）
  **根因**：替换串空格数/全半角与原文不符
  **防御**：先 Select-String 原文核对再 Replace；先长后短

- **现象**：行级替换切坏 .ps1——用"行号定位起止+数组重组"替换 forgeEngineCmdList.ps1 的函数段，定位错位切掉文件大段，dot-source 报 ParserError（Unexpected token '}'）
  **根因**：函数结尾用"行首恰为 }"判定，文件内其他行首 } 干扰匹配；函数实际在文件末尾，行号假设错误
  **解决**：git checkout -- 文件恢复 HEAD 底稿 → 纯追加（ReadAllText + 末尾拼接 + WriteAllText 保 BOM/CRLF）重建
  **防御**：①向现有 .ps1 加函数一律"末尾纯追加"，禁止行级替换/数组重组 ②动手前 git ls-files 确认有底稿可回滚 ③验证文件干净先 Remove-Item function:xxx 清内存残留再 dot-source（否则旧函数仍在会话，Get-Command 误判未改干净）④加分区注释前先 Select-String '^# [一二三四五六七八九十]+、' 查已有编号（本次误写"三、"实为"七、"，撞"三、查看"）
## CMake / 构建类

- **现象**：CMakePresets.json 加 // 注释 → JSON Parse Error
  **根因**：preset 解析不接受注释（实测）
  **防御**：preset 保持严格 JSON；说明写文档
- **现象**：目录改名后 cmake 报 CMakeCache 路径不匹配
  **根因**：cache 固化旧绝对路径
  **解决**：fe-clean（删 build\vs，保留 vcpkg_installed）→ 重配
- **现象**：ForgeEngine.dir / x64 / Debug 等空目录与中间目录
  **根因**：VS 生成器硬编码（IntDir 不可配）
  **防御**：接受；exe 已收 bin\output
- **现象**：VS 出现 "CMake Rules" 节点
  **根因**：自定义规则输出文件（spv）进了 target_sources
  **解决**：assets GLOB 排除 shader\（规则产物）
- **现象**：exe 输出目录写死绝对路径
  **根因**：CMAKE_BINARY_DIR 展开（CMake 设计）
  **防御**：别手动改 vcxproj，改 CMakeLists 的 RUNTIME_OUTPUT_DIRECTORY
- **现象**：想自定义 "Fast" 配置档 → vcpkg 失败
  **根因**：vcpkg 只认内置配置名（非标准配置转储/链接错库）
  **防御**：不自定义新配置名；用内置 RelWithDebInfo 重定义 flags（现配置集 Debug;Release;RelWithDebInfo，RelWithDebInfo=/DNDEBUG /Od /Zi 快速日常档，带 PDB 可断点）
- **现象**：单 TU Release /O2 全量 ~12.4s（/d1reportTime：前端 ~2.8s、后端 ~9.6s）；/cgthreads8 无效
  **决策**：日常用 RelWithDebInfo（~6s）；Release 仅发布/优化验证跑 → 现阶段不拆 TU
  **根因**：全 inline 头设计 → codegen 锚定调用点（main→Pipeline::drawFrame/ctor→Plate/Buffer/3 worker 全链）；"世界/初始化/帧/工具"4 路均分需所有权解耦（Plate 移出 Pipeline）+ namespace 全局 inline 化（VkInfo.h engineInfo/lockInfo/getLock 等 LNK2005 风险），现实上限 ~6-7s
  **防御**：复评触发 = 全量 >20s 或频繁改头文件痛感明显；届时先做 Pipeline 方法定义下沉 graphic\Pipeline.cpp（声明留类内）→ 再做 Plate 解耦；任何多 TU 前先 C0：namespace 级非 inline 全局改 inline

## vcpkg 类

- **现象**：cmake --preset vs 突然全量重建 22 包
  **根因**：triplet/portfile/baseline 内容变 → ABI 变
  **防御**：triplet 改动要预期一次性重装（跑完即稳）；勿随意加空格改内容
- **现象**：改 triplet 注释也触发重建？（待验证——若 vcpkg 按文件 hash 计 ABI，注释也变）
  **防御**：triplet 尽量少动；动前知晓会重建
- **现象**：vcpkg.json 删依赖行后，已装包仍留在 vcpkg_installed？
  **解决**：删行 → cmake --preset vs → manifest 自动卸载（实测删除 forgeengine-stb-font："Removing 1/1...8.49ms"，无需手动删目录）
  **防御**：删库=vcpkg.json 删一行 + reconfigure；以 vcpkg 输出"will be removed"为准，残留无害
- **现象**：装 VS2026 后 vcpkg 自动抢用其工具集（vswhere -latest）；VS 内 reconfigure 触发全量 60 包重装；链接报 ktx LNK2019 __std_unique_4
  **根因**：vcpkg 无视 vcvars/VCToolsInstallDir，固定 vswhere -latest 选最新 VS；依赖库(vs2026/14.51)与 exe(vs2022/14.44)工具链不同 → STL 内部符号不匹配
  **解决**：setx VCPKG_VISUAL_STUDIO_PATH=<vs2022路径> + VCPKG_PLATFORM_TOOLSET=v143 → vcpkg install 全量重装回 vs2022（binary cache 秒回）
  **防御**：多 VS 共存先设这两环境变量再动 vcpkg；exe 与 vcpkg 库必须同工具链，勿混链

## VS 类

- **现象**："新建解决方案资源管理器视图"关掉就没了
  **根因**：VS 不持久化新建视图（设计如此）
  **防御**：用主视图+设为启动项目；fe-clean 会清 .suo（视图状态重置）
- **现象**：VS 启动下拉 4 个工程（ForgeEngine/ALL_BUILD/ZERO_CHECK/ForgeShader）
  **根因**：CMake 生成器固有辅助工程，不可删
- **现象**：解决方案配置曾有 4 种（含 MinSizeRel）
  **解决**：CMAKE_CONFIGURATION_TYPES 收敛；现为 Debug;Release;RelWithDebInfo（RelWithDebInfo 加回=快速日常档，非历史遗留）

## git / 改名类

- **现象**：改文件名/脚本名后某处引用失效
  **防御**：改名链 = git mv + 全仓 Select-String 搜引用（含 profile/docs）+ 同步
- **现象**：远端仓库改名后 push 失败
  **解决**：git remote set-url origin 新 URL；旧链接 GitHub 自动重定向

## AI 协作 / 文档类

- **现象**：AI 消息外层 ``` 内又嵌 ```（md 代码块）→ 消息截成三段
  **根因**：代码围栏嵌套冲突，Markdown 提前闭合
  **防御**：文档正文代码块用 4 空格缩进式；外层围栏用 4 反引号
- **现象**：批量整文件覆盖时，换行风格/尾换行/BOM 被改 → 全文件假 diff
  **解决**：Write-Doc 模板 = here-string 存内容 → 读原文件判 EOL（含 \r\n 用 CRLF 否则 LF）→ 统一替换 → WriteAllText(UTF8 无 BOM)，内容末行无尾换行
  **防御**：多文件覆盖一律走该模板；写后 git diff --stat 核对行数而非全量

## 渲染/引擎类

- **现象**：HUD fps 静止时只显示数值首位（随 ~1000 帧率在 1/9 间变），其余位不绘制；破坏方块/跨板块移动（触发命令重建）后恢复正常。fps 传入值、段文本、written 计数均正确（142→145 随位数变化）
  **根因**：命令缓冲非每帧重录（createCmd 只录一次，板块/方块/换链时才 recreateCmd）；uiText 的 vkCmdDraw 顶点数在录制时按当时 uiText.numLetters 烘焙进命令。文本内容变长超出烘焙数后，末尾字形不再绘制，直到下次命令重建重新烘焙。坐标行正常 = 每值 padFixedWidth(10) 定长、字形数恒定且落在烘焙范围内；fps 改 std::to_string 变长后踩坑（旧版 setw(8) 定长未踩）。初始化 drawUIText(1000) 只是碰巧够用
  **解决**：fps 值定长补位 padFixedWidth(std::to_string(fps), 8)，总字形数恒定 = 命令烘焙数
  **防御**：凡 uiText 文本一律定长补位（坐标 x:/y:/z:、fps、后续中文行）；改任何行内容长度时检查烘焙顶点数与总字形数是否恒定；勿依赖"init 用大值碰巧够用"

## dsh 试点类

- **试点结论**：dsh（DeepSeek Harness 0.1.2-rc）作为 ForgeEngine 执行体试点判定：方案 C（Chatbox 大脑 + dsh 执行体）成立
  **实测事实**：pwsh 持久会话；fe- 指令跨会话可用（免 dot-source）；只读命令零审批；中文读写无乱码
  **环境约定**：DSH_HOME=E:\tool\app\dsHarness；Node v24.20.0（E:\tool\app\node）；npm cache 在 E 盘
  **关键坑**：Windows 下 .NET SetEnvironmentVariable 不广播 WM_SETTINGCHANGE，装完 node 后新终端 PATH 不生效；需重启或手动补 PATH


## Chatbox / 知识库类

- **现象**：Chatbox KB 与仓库不同步（仓库改 ≠ KB 自动更新）；同步时踩重复/格式坑
  **要点**：①同名拖入 = 新增重复条目、非覆盖（实测 2026-09-08），同步必须先删旧再拖 ②官方无自动同步（issue #2464 仍 Open）③格式白名单：pdf/docx/txt/md/rtf/pptx/xlsx/csv/epub+图片；json 不支持；.h/.hpp/.cpp 实测可传 ④白名单外格式（.json/无扩展名）复制为 <原名>.txt 再拖入即可解析 ⑤变更文件 >8 个时直接删库重建+全量拖入，比逐个删旧快（41 文件重建验证通过）
  **防御**：改 docs/代码后跑 fe-sync-kb（仓库根，集合展开+SHA256 增量+格式适配+残留清理 → docs\chatbox-sync\）→ KB 删同名旧文件 → 拖变更文件；KB 只是仓库影子的手动快照，勿依赖自动同步
